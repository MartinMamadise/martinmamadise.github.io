Architecture

SDN · Network automation

SDN Traffic Engineering & Network Management App

  • Python
  • Tkinter
  • OpenDaylight
  • RESTCONF
  • PCEP
  • BGP-LS
  • MPLS
  • GNS3
  • IOS XRv
GitHub

An operator-facing network management application for a three-router IOS XRv full-mesh MPLS network emulated in GNS3 and controlled by OpenDaylight. It reads live topology and LSP state from the controller over RESTCONF, compares the direct R1→R3 path against the transit path via R2 under a changing traffic demand, and recommends a re-route when a link passes its congestion threshold. Operators can then provision, re-route and tear down a PCE-initiated LSP from the GUI, with every step verified against controller and router evidence rather than trusting an API response.

Architecture, rigour & outcomes

Architecture

Operator GUI (Tkinter) → application logic (telemetry, path computation, state) → adapters for the OpenDaylight RESTCONF API, the GNS3 REST API and read-only router CLI over console → OpenDaylight PCE and IOS XRv nodes → MPLS network. Frontend and backend are cleanly separated into gui/ and ga5app/, using only the Python standard library.

Engineering rigour

Every value is tagged MEASURED, CONTROLLER, ASSUMED, COMPUTED or SIMULATED so the operator never mistakes an estimate for telemetry. An LSP is drawn as operational only when the controller reports it up, and teardown is confirmed by its absence. 22 automated tests, a health audit and a full audit trail cover the logic.

Key outcomes

Under a 6.474 Mbit/s demand the direct link reaches 84.7 % (congested); re-routing via R2 brings the maximum utilisation down to 69.7 %. For an overload the app computes a 42/58 traffic split. Demand and test parameters are derived from my student number, and the project discloses its use of AI assistance.

Smart Agriculture Monitoring System

  • ESP32
  • C/C++
  • IoT
  • Sensors
  • Firebase
GitHub

A multi-sensor smart irrigation system built on Arduino and ESP32 that monitors and manages agricultural conditions in real time. It collects soil moisture, ambient light and water-reservoir level, transmits the data over WiFi to a remote interface and logs it to track trends over time. An I²C LCD gives on-site feedback while an embedded control algorithm uses sensor thresholds to regulate irrigation through a relay-controlled valve — a practical, scalable way to improve water efficiency in resource-constrained farming.

Stack & outcomes

Software

C/C++, HTTP client–server communication, REST API integration, WiFi/TCP-IP on ESP32, Firebase (cloud database), MIT App Inventor (mobile UI).

Hardware

ESP32, capacitive soil-moisture sensor, LDR for light, HC-SR04 ultrasonic for water depth, relay module for valve control, I²C 16×2 LCD.

Key outcomes

Continuous remote visibility of field conditions without manual inspection, trend analysis from logged data, timely detection of changes and more efficient water use through automated control.

Solar-Powered Washing Machine Controller

  • Embedded
  • Solar
  • ATmega328P
  • C++
  • Energy management
GitHub

An embedded controller that lets a washing machine run entirely on solar power by monitoring available energy and adjusting the cycle in real time. It manages fill, wash, rinse, drain and spin autonomously — pausing and resuming with fluctuating sunlight to avoid failures. Designed for South Africa's load-shedding and off-grid conditions.

Stack & outcomes

Software

Arduino IDE (embedded C/C++), Tinkercad for circuit simulation and validation, IRremote library for infrared power-level input.

Hardware

Arduino Uno (ATmega328P), 50 W solar panel, 12 V battery buffer, ADC water-level sensing, L298N motor driver, stepper drum motor, DC pump, solenoid valve, transistor switching and diode protection.

Key outcomes

Full off-grid operation in good sun; power-aware control prevents mid-cycle failures by pausing in low energy and resuming automatically — a low-cost model for pairing renewables with household appliances.

Traffic Engineering with Graph Theory & Linear Programming

  • Networking
  • Graph theory
  • Linear programming
  • Python
  • Optimisation
GitHub

A network optimisation system that models and improves traffic flow in large networks. It compares shortest-path routing against multi-commodity flow optimisation on the NSFNET backbone topology, distributing traffic across multiple paths to minimise congestion and maximise resource use.

600% → <75%maximum link utilisation after Multi-Commodity Flow with Min-Max Utilisation
Stack & outcomes

Software

NetworkX (graph modelling, shortest paths), PuLP + CBC solver (LP formulation), Pandas (demand generation), Matplotlib (utilisation plots).

Key outcomes

Used Dijkstra's algorithm as a baseline; showed that Single-Commodity Flow minimises cost but congests badly and scales poorly. Multi-Commodity Flow with Min-Max Utilisation balanced load, improved resilience and demonstrated traffic-engineering strategies used in modern networks.
